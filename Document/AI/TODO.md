# 남은 작업과 보류 결정

완료 항목을 누적하지 않는다. 같은 주제는 기존 항목을 수정한다. 아래 순서는 점검 순서이며 사용자 승인 없이 새 구현을 시작하는 목록이 아니다.

| 순서 | 항목 | 상태 | 근거 |
|---|---|---|---|
| 1 | 최신 허브/친구/세 게임의 Android 실제 기기 확인 | 남은 검증. 과거 APK/Editor 통과와 구분 | [검증](../../Agent_Instruction/Verification.md), [현재 허브](../Human/Hub_UI.html) |
| 2 | 남아 있는 개발 로그/예외 문구의 문자열 테이블 적용 | 기존 잔여. 해당 코드 변경 시 검토, 일괄 리팩터링 미요청 | `GameBootstrap.cs`, `StringTable.cs`, `JsonSaveRepository.cs`, [UI 계약](../../Agent_Instruction/UI.md) |
| 3 | 과거 생성 도구의 Logs 백업 경로·초기 스타일 재적용 영향 | 도구 수정/재실행 전에 검토 | [함정](../../Agent_Instruction/Pitfalls.md) |
| 4 | Google 선택적 연동·서버/DB·클라우드 저장 | 제품/기술 결정 대기 | [사용자 결정](Project_Decisions.md) |
| 5 | 원판/시간 분신의 영구 기록·코인, 배달 재활성화 | 별도 결정 대기. 현재판 규칙·기존 저장 유지 | [게임 계약](../../Agent_Instruction/MiniGames.md) |

## 확인 범위

- 항목 1은 기기 터치·safe area·재실행 저장·성능을 포함한다. 이번 지침 적용에서는 게임 실행/Android 빌드를 하지 않았다.
- 항목 2는 코드에 기존 문장 리터럴이 남아 있다는 뜻이다. 문자열 테이블 자체가 실패할 때의 진단 경로를 포함하므로 문구를 기계적으로 치환하지 않는다.
- 항목 3은 생성 메뉴가 현재 프리팹을 과거 디자인으로 되돌릴 수 있는지 확인하는 작업이다. 아직 손상됐다고 단정하지 않는다.
- 새 계획이 커지면 `Plan/`에 문서를 만들고 이 목록에 연결한다. 확정된 외부 담당자·기한은 현재 없다.
