## 2026-09-17 — 씬 흐름 및 선택적 계정 연동

- 씬 흐름은 `BootScene → SelectScene → GameScene`으로 확정한다.
- `BootScene`: 초기화와 로컬 데이터 로드 후 SelectScene 진입. 로그인 필수 관문을 두지 않는다.
- `SelectScene`: 게임·캐릭터 선택 및 계정 연동 진입점. 미연동 상태에서 언제든 Google 계정 연동을 시작할 수 있어야 한다.
- `GameScene`: 선택된 미니게임 실행. 첫 미니게임 이름은 Block Gravity이며 씬 파일 이름은 GameScene이다.
- 로그인 없이 게스트로 게임을 플레이할 수 있어야 한다.
- Google 계정 연동 취소·실패가 게스트 플레이를 막지 않도록 한다.
- 이번 변경은 씬 상수·설정 도구·설계 문서에 반영한다. 인증 SDK·서버 통신은 아직 구현하지 않는다.
- 인증 제공자 구성, Google 연동 세부 방식, 게스트 데이터 이전·병합, 계정 해제, 클라우드 저장 도입 여부와 구현 시점은 미정이다.
- Supabase DB와 웹서버 구상은 여전히 검토안이며, 이 요구사항만으로 특정 백엔드를 확정하지 않는다.

## 2026-09-18 — 주요 기능은 싱글톤 매니저로 관리

- 사용자 결정: 주요 기능은 싱글톤 매니저로 관리한다. 예: 사운드 매니저, 데이터 매니저.
- DataManager: 캐릭터·게임 카탈로그, 선택·코인·설정 조회, 로컬 저장 변경의 진입점. PlayerProfile과 ISaveRepository는 내부 역할 분리를 위해 유지한다.

- SceneFlowManager: 게임 이용 가능 여부와 씬 이동의 싱글톤 진입점. 기존 SceneFlow 실행 로직을 사용한다.
- GameBootstrap은 같은 루트의 매니저들을 Data → Sound → SceneFlow 순서로 초기화하고 DontDestroyOnLoad로 유지한다.
- 중복 초기화 거부, 명시적 Shutdown, 이벤트 구독 해제, 정적 참조 초기화를 포함한다.
- 실제 사운드 에셋과 기본 BGM 지정은 이번 변경에 포함하지 않는다. UI 클릭 클립은 선택적으로 연결하며 미지정 시 무음이다. 기본 BGM 재생 호출은 아직 연결하지 않았다.
- 캐릭터 테이블 형식 변경, 서버·인증, Block Gravity 로직 구현을 승인한 것으로 해석하지 않는다.

## 2026-09-18 — UIManager 추가와 프리팹 구조 우선

- 사용자 요청: 게임 로직 전에 구조를 정리하며 UIManager도 둔다.
- UIManager를 네 번째 싱글톤 매니저로 추가했다. 초기화 순서는 Data → Sound → SceneFlow → UI → 허브 진입이다.
- UIManager 책임: 패널 전환, 뒤로가기 이력, 허브 복귀 시 이력 초기화, 안내 표시, 현재 씬 UISceneView 등록/해제.
- HubView와 GameEntryView는 UISceneView를 상속한다. 버튼·텍스트·패널 참조와 실제 표시 작업은 View가 담당한다. 기존 직렬화 필드는 유지했다.
- View 등록은 초기화 후 수행한다. OnDisable에서 해제하고 재활성화 시 재등록한다. 파괴된 View로 들어오는 늦은 요청은 상태를 정리하고 거부한다.
- DataManager는 데이터 변경, SoundManager는 소리, SceneFlowManager는 실제 씬 로딩을 계속 담당한다.
- 현재 안내는 기존 텍스트 영역이다. 모달 팝업 프리팹, 공통 UI 프리팹 추출, 프리팹 로딩/캐시와 ResourceManager는 아직 구현하지 않았다.
- 프리팹 분리에서는 GameManagers의 bootStatus 같은 씬 참조를 분리해야 한다. 현재 변경만으로 프리팹 구성이 완료됐다고 보고하지 않는다.

## 2026-09-19 — 모든 게임 리소스는 로컬 부트 로딩, 원격 패치 미사용

- 프로그레스바·퍼센트·준비 단계·재시도 버튼을 갖춘 BootLoadingUI 프리팹 생성 도구를 제공한다.
- Assets/_Project/Resources 게임 에셋을 스캔하여 JSON 목록에 등록. 기존 선택 슬롯은 유지하고 새 파일은 필수로 추가. 씬/카탈로그가 직접 참조한 부트 UI 및 의존 에셋은 Unity의 부트씬 로딩으로 준비된다.
- 런타임 기본 Spawn의 동기 Resources.Load fallback을 제거. 부트 완료 전에 생성 금지, 부트 완료 후 새 Preload 금지. 부트 미등록 에셋은 캐시에서만 찾다가 명시적으로 실패한다.
- Editor Play/Build에서 실제 Resources 파일과 등록 목록의 일치 검사. 신규 리소스를 넣으면 Boot 구성 메뉴로 목록을 갱신한다.
- Runtime 자산은 Resources 또는 기존 부트 카탈로그/프리팹 의존성으로 연결한다. 사용하지 않는 작업용 원화·에디터 파일까지 부트 로딩 대상에 넣지 않는다.
