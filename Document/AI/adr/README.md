# 구조 결정 기록

[문서 색인](../README.md) · [작성 틀](../ADR-Template.md) · [현재 기능 계약](../../../Agent_Instruction/README.md)

되돌리기 어렵고 여러 기능에 영향을 주는 결정의 이유를 보존한다. 단순 구현 세부·작업 일지는 기능 문서/TODO/Git에서 관리한다.

## 작성과 상태

1. `NNNN-짧은-이름.md`로 만들고 상황·결정·기각한 대안·감수할 점·재검토 조건을 적는다. 번호는 이 폴더의 현재 목록을 확인해 중복 없이 부여한다.
2. 검토 중이면 `proposed`, 승인 근거가 확인된 결정만 `accepted`다. 요청 범위 안의 구현 선택과 별도 제품 결정이 필요한 선택을 구분한다. ADR 자체가 권한이나 승인을 대신하지 않는다.
3. accepted 결정이 바뀌면 새 ADR을 작성하고 기존 상태를 `superseded by NNNN`으로 바꿔 서로 연결한다. 당시 결정 이유는 보존한다. 오탈자/링크 교정과 proposed 초안 보완은 기존 파일에서 할 수 있다.
4. 현재 동작 계약은 Agent_Instruction, 현재 위치는 ARCHITECTURE에서 갱신하고 ADR은 이유로 연결한다. 같은 규칙을 여러 문서에서 원본으로 관리하지 않는다.
5. [기존 사용자 결정](../Project_Decisions.md)은 그대로 보존한다. 모든 과거 결정을 새 ADR로 일괄 복제하지 않으며 근거 없는 대안·승인 날짜를 만들지 않는다.

## 색인

현재 새 형식으로 등록한 ADR은 없다. 이 지침 도입은 게임 구조를 새로 결정한 것이 아니다. 향후 실제 결정이 생기면 번호·제목 링크·상태·대체 관계를 여기에 등록한다.
