Transform 중복 연결 경고의 원인과 수정

이전 코드가 UI 참조를 교체하면서 Transform의 내부 자식 목록도 변경했습니다. 새 오브젝트는 이미 부모에 연결돼 있어 같은 자식이 두 번 연결되는 경고가 발생했습니다. Unity가 중복 링크를 제거했지만, 이 동작에 의존하면 안 됩니다.

이제 UI 컴포넌트가 선언한 직렬화 필드만 교체합니다. Transform 부모·자식 목록, GameObject 소유권과 프리팹 내부 메타데이터는 건드리지 않습니다. 자식 순서·부모 관계 보존 검사와 배열·버튼 탐색 참조 검사도 추가했습니다. 전체 생성 메뉴를 다시 실행한 검증이나 실제 Play 확인은 아직 하지 않았습니다.

처음 적용할 때의 순서

이미 생성 메뉴를 실행했다면 위의 최신 적용 상태에 따라 검사 메뉴와 Play 확인만 진행하세요.

  1. Play 모드를 종료하고 C# 컴파일 완료를 기다립니다. 기존 Phase 1 씬이 없는 프로젝트에서만 먼저 Pocket Arcade → Phase 1 → 1. Create Hub And Data를 실행합니다.
  2. Pocket Arcade → UI Foundation → 1. Create Prefabs And Migrate Scenes를 실행합니다. 현재 수정한 씬의 저장 여부를 확인한 뒤 씬 원본을 백업하고, 공통 UI·패널·화면·매니저 프리팹을 생성합니다.
  3. Pocket Arcade → UI Foundation → 2. Validate Prefabs And Scenes를 실행합니다. 누락된 참조와 화면 로딩 경로를 검사합니다.
  4. BootScene에서 Play하고 허브 → 설정 → 게임 → 허브를 이동합니다. 자세한 검증 항목은 아래에 있습니다.

씬 백업은 Client/Logs/UIFoundationBackup/날짜-시간/에 저장됩니다. 재실행 시 기존 프리팹 파일을 덮어쓰지 않습니다. 중간 오류가 나면 Console을 확인하고 백업 씬으로 복구할 수 있습니다. 원본 씬의 .meta는 그대로 유지합니다.

기존 Phase 1이 만든 UI 계층을 기준으로 추출합니다. 공통 프리팹과 원본 컨트롤의 자식 이름이 다르면 무리하게 합치지 않고 중단합니다. 화면별 위치·문구·색은 프리팹 인스턴스의 override로 유지됩니다.

HubView / GameEntryView

직렬화한 버튼·텍스트·이미지 참조를 보유하고 화면을 갱신합니다. 입력을 이벤트로 전달하며 저장과 씬 이동은 Controller가 수행합니다. 시작 시 Controller 구성과 UI 등록을 연결합니다.

HubController / GameEntryController

View의 이벤트를 구독해 DataManager·SoundManager·SceneFlowManager를 호출합니다. 저장 실패 시 표시를 복구하고 안내를 요청하며 종료 시 구독을 해제합니다.

UIManager / UIFeedback

패널 이력, 메시지박스 대기열, 팝업 스택, 툴팁·토스트 인스턴스를 관리합니다. 모달이 떠 있으면 뒤쪽 UI의 입력을 막고, 씬 종료 시 정리합니다.

ResourceManager / UISceneHost

Resources 경로로 프리팹을 로드·캐시하고 생성한 인스턴스를 추적합니다. 씬의 Host는 화면 프리팹을 생성하고 씬이 닫히면 반환합니다.

초기화 순서: Resource → Data → Sound → SceneFlow → UI → 허브. 매니저 5개는 같은 영속 루트에 있습니다. 부트 오류 텍스트는 씬의 BootStatusView로 분리해 매니저 프리팹이 씬 텍스트를 참조하지 않습니다.

뒤로가기는 메시지박스 취소 → 맨 위 팝업 닫기 → 이전 패널 순서입니다. 패널 이동 API도 모달 표시 중에는 거부합니다. 키보드 Escape를 연결했고 Android 뒤로가기의 실제 기기 동작은 별도 확인이 필요합니다.

리소스 해제와 인스턴스 파괴의 차이

Release(instance)는 생성된 화면을 비활성화하고 파괴합니다. 같은 경로의 살아 있는 인스턴스가 있으면 Evict(path)는 캐시를 지우지 않습니다. TrimUnused()는 사용하지 않는 캐시 참조를 제거하고 Unity에 미사용 에셋 정리를 요청합니다.

프리팹이 다른 화면에 중첩되었거나 외부에서 참조 중이면 실제 메모리 해제 시점은 달라집니다. 닫을 때마다 정리 작업을 돌리지 않으며, 로딩 구간 등에서 명시적으로 호출합니다. 현재는 로컬 MVP용 Resources 방식이며 Addressables·원격 다운로드는 포함하지 않습니다.

풀링 범위

툴팁·토스트·메시지박스는 각각 인스턴스 1개를 재사용합니다. 범용 오브젝트 풀과 동적 목록 가상화는 구현하지 않았습니다. 캐릭터 카드는 현재 카탈로그 수만큼 화면 프리팹에 포함되며, 카탈로그 수 변경 시 카드 구성도 맞춰야 합니다.

생성 메뉴 실행 후의 프리팹 위치

Client/Assets/_Project/
├─ Prefabs/Common/GameManagers.prefab
└─ Resources/UI/
   ├─ Common/       Button · Toggle · CharacterCard · MiniGameCard
   ├─ Panels/       Home · Characters · Games · Settings
   ├─ Screens/      Hub · GameEntry
   └─ Overlays/     Tooltip · Toast · MessageBox · Popup

UI는 Resources에서 로드하기 때문에 Resources/UI/ 아래에 둡니다. 화면 안에서 공통 컨트롤과 패널은 중첩 프리팹으로 연결됩니다. 씬에는 Canvas·SafeArea·UISceneHost가 남고 화면은 실행 중 생성됩니다.

공통 모양은 Common 프리팹에서, 화면별 배치는 Panels 또는 Screens 프리팹에서 수정하세요. 위치·문구·색에 인스턴스 override가 있으면 그 속성은 공통 프리팹을 바꿔도 그대로 유지됩니다. Scene에 표시된 런타임 복제본의 수정은 저장되지 않습니다.

코드에서 사용하는 방식

// 패널
UIManager.Instance.ShowPanel(UIPanel.Settings);
UIManager.Instance.Back();

// 알림과 툴팁 (등록된 화면이 필요)
UIManager.Instance.ShowToast("Saved", 2f);
UIManager.Instance.ShowTooltip("Character information", targetRect);
UIManager.Instance.HideTooltip();

// 확인 결과는 요청한 쪽에서 처리
var result = await UIManager.Instance.ShowMessageBox("Confirm", "Continue?");
if (result == MessageBoxResult.Confirmed)
{
    // Controller에서 후속 작업. 씬/View 수명도 확인.
}

// 기본 팝업을 복제해 화면별 내용으로 확장 가능
UIManager.Instance.OpenPopup("UI/Overlays/Popup");

메시지박스는 Confirmed / Cancelled / SceneClosed를 반환합니다. 씬이 닫히면 요청이 무한 대기하지 않습니다. 재사용할 때 이전 응답 이벤트와 텍스트를 초기화합니다. 툴팁·토스트 API가 준비돼 있지만 모든 버튼에 툴팁 문구를 붙인 상태는 아닙니다.

실제 화면에서 확인할 항목

  1. 부트 → 허브 진입 후 GameManagers가 1개이고 ResourceManager를 포함한 매니저 5개가 초기화됐는지 확인합니다.
  2. 설정 패널을 여러 번 열고 토글을 바꿉니다. 한 번의 조작에 저장이 중복되지 않고 재실행 후 설정이 유지돼야 합니다.
  3. Google 계정 버튼으로 메시지박스를 열고 뒤쪽 버튼이 눌리지 않는지 확인합니다. 확인·취소 후 원래 화면 조작이 복구돼야 합니다.
  4. 잠긴 게임 카드의 토스트를 확인합니다. 여러 알림이 순차적으로 사라져야 합니다.
  5. 허브 → 게임 → 허브를 반복합니다. 이전 화면·오버레이가 남지 않고 매니저가 중복되지 않아야 합니다.
  6. 툴팁 위치·팝업 순서·뒤로가기·Safe Area를 세로 화면과 실제 Android 기기에서 확인합니다.

Edit Mode 검사는 상태·이벤트·수명 로직을 검증합니다. 실제 Raycast·터치·화면 렌더링·씬 로딩의 Play Mode 검증을 대신하지 않습니다. 사용자 제공 로그로 생성·검증 메뉴 실행을 확인했습니다. 수정 후에는 참조 교체 회귀 검사와 생성된 프리팹 14개 검사를 수행했으며, 전체 생성 메뉴는 재실행하지 않았습니다.
