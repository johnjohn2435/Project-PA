POCKET ARCADE / UI ARCHITECTURE

화면 전환은 UIManager가,
화면 표시는 View가

네 번째 싱글톤 매니저를 추가하고 허브의 화면 관리 역할을 분리했습니다. 프리팹으로 옮길 때도 UI 내부 참조는 View가 소유하도록 구성했습니다.

코드 연결 완료 · Android 타깃 Edit Mode 55/55 통과 · 새 구조의 Play Mode 확인은 남아 있음

주요 기능 매니저 4개

DataManager

캐릭터 목록, 현재 선택, 코인, 설정과 저장.

SoundManager

BGM·효과음 재생과 저장된 소리 설정 반영.

SceneFlowManager

허브와 게임 사이의 실제 씬 이동, 게임 이용 가능 여부 검사.

UIManager — 이번 추가

씬 내부 패널 전환, 뒤로가기, 안내 표시, 활성 UI View 등록과 해제.

초기화: Data → Sound → SceneFlow → UI → 허브. Game Services 루트와 매니저는 씬 전환 간 유지됩니다.

버튼을 눌렀을 때의 흐름

HubView캐릭터 버튼 클릭
→
UIManager현재 패널·뒤로가기 이력 관리
→
HubView요청받은 패널 표시

View는 버튼과 텍스트, 패널 오브젝트를 알고 있습니다. UIManager는 현재 등록된 View에 표시를 요청합니다. 저장이나 실제 씬 로딩은 각각 DataManager와 SceneFlowManager가 맡습니다.

UIManager.Instance.ShowPanel(UIPanel.Characters);
UIManager.Instance.ShowPanel(UIPanel.Settings);
UIManager.Instance.Back();
UIManager.Instance.ShowHome();
UIManager.Instance.ShowNotice("준비 중입니다.");

초기화와 View 등록 후 호출합니다. GameEntry 화면에서 캐릭터 패널처럼 지원하지 않는 패널을 요청하면 false를 반환합니다.

씬이 바뀌면 UI 참조도 정리합니다

  1. 씬의 View가 초기화되면 UIManager에 등록하고 기본 패널을 표시합니다.
  2. 패널을 바꿀 때 이전 패널을 이력에 넣습니다. 같은 패널을 다시 여는 요청은 이력을 늘리지 않습니다.
  3. 뒤로가기는 이전 패널로, ShowHome은 이력을 비우고 허브 기본 패널로 돌아갑니다.
  4. 씬 종료나 View 비활성화 시 등록을 해제합니다. 재활성화 시 다시 등록합니다.
  5. 늦게 도착한 요청의 View가 이미 파괴됐다면 참조·이력을 정리하고 요청을 거부합니다.

매니저에 씬의 버튼·텍스트를 직렬화하지 않습니다. UISceneView를 통한 런타임 등록 구조이므로, View의 내부 참조를 유지한 채 프리팹으로 분리할 수 있습니다.
