동작을 선택하면 처리 순서와 담당 코드가 바뀝니다.

  1. 캐릭터 카드 클릭HubView → DataManager
  2. 새 선택값 준비PlayerProfile이 데이터를 복사
  3. 파일 저장JsonSaveRepository가 JSON 기록
  4. 허브 갱신Changed 이벤트 → 이미지·이름 반영

저장은 언제 일어나나요?

캐릭터 선택과 설정 변경 시 즉시 저장합니다. 저장 성공 후에만 현재 프로필을 바꾸므로 실패한 선택이 화면에 남지 않습니다.

player-save.json → 손상 시 .bak 복구 → 백업도 읽을 수 없으면 기본값으로 시작합니다.

원화는 어디에 넣나요?

CharacterDefinition의 Portrait에 스프라이트를 연결합니다. 모모·보리·나비의 최종 원화로 바꿀 때 게임 코드를 수정할 필요가 없습니다.

더미가 없으면 대표 색으로 표시합니다. 현재 게임 UI 문구는 기본 TMP 글꼴에 맞춘 영문입니다.

현재 게임 화면은 입구까지입니다. Block Gravity의 보드·배치·중력·점수와 실제 Google 로그인은 아직 구현하지 않았습니다. 코인은 저장 구조와 유지까지 포함하며 보상 지급은 이후 단계입니다.

주요 기능은 싱글톤 매니저로 관리합니다

GameBootstrap은 초기화 순서와 수명을 관리합니다. 각 화면은 필요한 매니저의 Instance로 기능을 호출합니다.

DataManager.Instance

캐릭터 · 저장 데이터

카탈로그, 선택 캐릭터, 코인, 설정.
PlayerProfile과 저장소를 연결합니다.

SoundManager.Instance

BGM · 효과음

배경음 반복 재생, 효과음 재생,
저장된 On/Off 설정을 반영합니다.

SceneFlowManager.Instance

게임 진입 · 씬 이동

이용 가능한 게임만 진입하고
로딩 중 중복 이동을 막습니다.

초기화 순서: DataManager → SoundManager → SceneFlowManager → 허브.
같은 Game Services 루트에 두고 씬이 바뀌어도 유지합니다. 중복 초기화는 거부하고 종료 시 이벤트 구독과 Instance를 정리합니다.
코드에서 호출하는 예시
DataManager.Instance.SelectCharacter("char_bori");
SoundManager.Instance.PlayBgm(bgmClip);
SoundManager.Instance.PlaySfx(effectClip);
SceneFlowManager.Instance.OpenGame("block_gravity", out string error);

초기화 완료 후 호출합니다. BGM·효과음은 AudioClip을 넘겨야 하며 현재 실제 음원과 자동 시작 BGM은 연결하지 않았습니다.

내부 코드는 역할별로 분리합니다

화면은 사용자의 입력을 전달하고, 프로필은 상태를 관리하고, 저장소는 파일을 다룹니다. 역할을 분리해 원화나 저장 방식을 바꿀 때 수정 범위를 줄였습니다.

Unity에서 화면을 적용하는 순서

실제 프로젝트는 D:\Project PA\Client입니다. 코드와 생성 메뉴는 준비됐고, 메뉴 실행 후 씬 동작을 확인해야 합니다.

  1. 프로젝트 열기 · TMP 기본 리소스 가져오기

    검증에 사용한 Unity는 6000.3.16f1입니다. 이미 가져온 리소스라면 생략합니다.

    Window > TextMeshPro > Import TMP Essential Resources
  2. Phase 0 기반 설정 확인

    미적용 상태라면 아래 메뉴를 1 → 2 → 3 순서로 실행합니다. Input System 변경 후 재시작 안내가 나오면 먼저 재시작합니다.

    Pocket Arcade > Phase 0 > 1. Apply Foundation
    2. Switch To Android → 3. Validate Foundation
  3. 허브와 데이터 에셋 생성

    캐릭터 3종, 게임 3종, 카탈로그와 세 씬의 UI를 연결합니다. 기존 에셋과 구성된 화면은 보존합니다.

    Pocket Arcade > Phase 1 > 1. Create Hub And Data
  4. 참조 검사 후 BootScene에서 Play

    검사 메뉴의 통과는 실제 플레이 검증과 별개입니다. 아래 체크리스트까지 확인합니다.

    Pocket Arcade > Phase 1 > 2. Validate Hub
    Assets/_Project/Scenes/BootScene.unity
이미 씬을 만들어 두었다면: Create Hub And Data를 다시 실행하세요. 기존 GameBootstrap 루트에 누락된 매니저만 추가하며 화면과 정의 에셋은 보존합니다. 이어서 Validate Hub를 실행합니다.
소리를 확인하려면: Game Services의 SoundManager에 Ui Click Clip을 연결하세요. 미지정이면 무음입니다. BGM은 PlayBgm에 클립을 전달해야 하며, 기본 BGM 자동 시작은 아직 연결하지 않았습니다.

씬 적용을 직접 실행해야 하는 이유

Unity MCP가 연결되지 않았을 때는 C#과 에디터 스크립트까지 준비하고 사용자의 에디터 실행 절차를 안내하라는 프로젝트 명세를 따랐습니다. 따라서 아직 Phase 1의 전체 완료 조건을 충족했다고 보지는 않습니다.

Unity 기준 버전으로의 업그레이드도 별도 미완료 항목입니다. 현재 메뉴는 기존 구성의 재생성 도구가 아니므로, 생성 후 원화나 화면을 변경할 때는 Inspector에서 편집합니다.
