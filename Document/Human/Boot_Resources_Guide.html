모든 게임 리소스는 로컬 빌드에 포함하고 부트에서 준비합니다. 원격 패치·다운로드·CDN은 사용하지 않습니다. 이전 Addressables 패치 검토안은 이 결정으로 대체됐습니다.

준비가 끝난 뒤에는 메모리의 캐시만 사용합니다. 빠뜨린 리소스를 게임 중에 추가로 읽는 기능은 차단했습니다. 신규 파일을 넣으면 위 Boot 구성 메뉴가 전체 게임 Resources 폴더를 스캔해 목록에 등록합니다. 등록 누락이 있으면 Play·빌드 전에 알려줍니다.

초상화는 Texture Type을 Sprite (2D and UI), Sprite Mode를 Single로 지정하세요. 이미 CharacterDefinition에 직접 연결된 초상화는 새 경로에 이미지가 없을 때 계속 사용합니다. 기존 원화와 캐릭터 이름·ID는 이번 작업에서 변경하지 않았습니다.

등록 목록 편집

BootResources.json에서 경로·타입·필수 여부를 관리합니다. 아직 없는 선택 슬롯은 직접 추가할 수 있습니다. 존재하는 파일은 Boot 구성 메뉴가 자동 등록합니다. 일반 텍스처·머티리얼·텍스트 데이터는 Asset 종류로 등록됩니다.

{
  "path": "Audio/SFX/Confirm",
  "kind": "AudioClip",
  "required": false
}

kind는 UI·캐릭터 프리팹의 Prefab, 초상화의 Sprite, 사운드의 AudioClip을 사용합니다. 같은 경로를 중복 등록하면 시작을 중단합니다. JSON 자체가 없거나 형식이 잘못돼도 부트에서 오류를 처리합니다.

캐릭터 정의는 GameCatalog가 제공하므로 JSON에 Definition 키를 중복 등록하지 않습니다. 현재 구조는 로컬 Resources 로딩입니다. 원격 다운로드·Addressables 패치는 사용하지 않는 것으로 확정했습니다.

실패 원인의 경로는 Console에 남깁니다. 재시도는 등록 목록부터 다시 읽으며, 이미 진행 중인 로딩 요청은 중복 실행하지 않습니다. 선택 리소스 누락은 정상적인 준비 상태로 처리합니다.

코드 구조와 사용

GameBootstrap
 ├─ BootResources.json 읽기
 ├─ BootResourceManifest.Parse() → 타입·중복 검사 + 캐릭터 슬롯
 ├─ ResourceManager.Preload() → LoadAsync + 캐시 + 진행률
 ├─ Data / Sound / SceneFlow / UI 초기화
 └─ 허브 진입

// 등록된 사운드 사용
var clip = ResourceManager.Instance.GetLoaded<AudioClip>("Audio/SFX/Confirm");
SoundManager.Instance.PlaySfx(clip); // 없으면 무음

// 준비된 캐릭터 프리팹은 실제 필요할 때 생성
var path = BootResourceManifest.CharacterPrefab(characterId);
if (ResourceManager.Instance.GetLoaded<GameObject>(path) != null)
    ResourceManager.Instance.Spawn(path, parent);
캐시 수명과 기존 직접 참조

부트에서 로드한 에셋은 세션 동안 캐시에 고정해 UI를 닫아도 다시 읽지 않습니다. Evict·TrimUnused는 이 에셋을 제거하지 않고, 매니저 종료 시 고정을 해제합니다. 생성된 인스턴스는 기존 Release 규칙을 따릅니다.

GameCatalog와 직접 연결된 캐릭터 정의·초상화는 Unity 씬의 에셋 참조로 이미 로딩될 수 있습니다. 부트는 이를 캐시에 등록하며, 새 Resources 경로의 초상화가 있으면 그 리소스를 우선 사용합니다.

확인할 것

  1. Boot 구성 메뉴 → 등록 검사 → BootScene Play. 로딩바·퍼센트가 진행된 후 허브 진입 확인.
  2. 사운드 파일이 없는 현재 상태에서도 시작되는지 확인.
  3. 기존 설정·캐릭터 선택·메시지박스·허브 복귀가 유지되는지 확인. 실패 시 Retry 버튼 표시와 다음 시도 때 진행률 초기화도 확인.
  4. 파일이 준비되면 위 경로에 추가하고 다시 Play하여 Boot 구성 메뉴로 목록을 갱신한 뒤 이미지·소리 반영 확인.

Edit Mode에서 실제 JSON 및 UI 리소스 비동기 로딩, 필수 누락·재시도, 선택 사운드, 초상화 대체, 타입 오류, 중복 로딩 거부, 취소 후 늦은 결과 차단, 프로그레스바 표시와 추가 로딩 차단을 검사했습니다. 전체 부트 흐름의 Play Mode·실제 기기·실제 음원 청취는 별도 검증입니다.
