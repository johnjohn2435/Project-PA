POCKET ARCADE / INDEPENDENT MANAGERS

매니저마다 독립 프리팹,
각각 독립 DDOL 루트

BootScene은 생성과 초기화 순서를 담당합니다. 초기화가 끝나면 Bootstrap은 씬과 함께 사라지고, 매니저 5개가 각각 살아남습니다.

코드·전환 도구 구현 완료 · Android Edit Mode 106/106 통과
사용자 제공 로그에서 매니저 분리·UI 참조 검증 성공을 확인했습니다. 이번 이름 정리: 씬 오브젝트는 Bootstrap, 컴포넌트는 GameBootstrap입니다. 아래 3번 메뉴를 다시 실행하면 기존 오브젝트 이름도 바뀝니다. 실제 Play Mode 수명 검증은 별도입니다.

Unity에서 적용

  1. Play 모드를 종료하고 컴파일 완료를 기다립니다.
  2. Pocket Arcade → Boot → 3. Separate Manager Prefabs를 실행합니다.
  3. Pocket Arcade → UI Foundation → 2. Validate Prefabs And Scenes로 분리된 매니저와 기존 UI 참조를 검사합니다.
  4. BootScene에서 Play하고 로딩 후 허브 진입과 각 DDOL 루트를 확인합니다.

BootScene은 Client/Logs/IndependentManagersBackup/에 백업됩니다. 기존 통합 GameManagers 프리팹은 GUID를 유지한 채 Assets/_Project/Prefabs/Legacy/로 옮기고 부트씬의 참조를 제거합니다. 기존 프리팹 파일 자체를 삭제하지 않습니다.

기존 클릭 사운드 클립 설정은 새 SoundManager 프리팹으로 옮깁니다. 이미 만들어진 개별 매니저 프리팹은 덮어쓰지 않습니다. 예전 루트에 다른 스크립트나 자식이 있다면 자동 삭제하지 않고 중단합니다.

각 매니저는 초기화 시 자기 GameObject를 DDOL로 전환합니다. 공통 PersistentManager는 루트 구조 검사와 DDOL 호출만 공유하는 기반 클래스입니다. 기능·정적 Instance·Shutdown은 각각의 매니저가 갖습니다.

생성·초기화·종료 흐름

  1. Bootstrap이 직접 참조한 ResourceManager 프리팹을 생성·초기화합니다.
  2. 등록한 모든 로컬 게임 리소스를 부트에서 준비합니다.
  3. Data → Sound → SceneFlow → UI 순서로 개별 프리팹을 생성·초기화합니다.
  4. 허브로 이동합니다. BootScene의 Bootstrap과 로딩 UI는 제거되며 각 DDOL 매니저는 유지됩니다.
  5. 부트씬을 다시 열어도 이미 초기화된 매니저가 모두 있으면 재사용합니다.

초기화 실패 또는 완료 전 부트씬 종료 시 만들어진 매니저를 정리합니다. UI → Sound → SceneFlow → Data → Resource 순서로 Shutdown 후 오브젝트를 제거하므로 재시도 때 이전 인스턴스가 남지 않도록 구성했습니다.

한 프리팹 안에 여러 매니저를 넣거나, 매니저를 다른 오브젝트 아래에 넣거나, 비활성화한 프리팹을 연결하면 구성을 거부합니다. 런타임 중복 singleton 초기화 거부도 유지합니다.

확인할 항목

  • 부트 로딩바 진행 후 허브가 열리는지
  • DDOL 씬에 위 매니저가 각각 1개씩 독립 루트로 있는지
  • 허브 → 게임 → 허브 이동 시 매니저가 중복 생성되지 않는지
  • 부트 재진입 시 기존 매니저를 재사용하는지
  • 설정·저장·사운드·메시지박스가 기존처럼 동작하는지

Edit Mode 106개 검사로 개별 루트 규칙·통합/중첩/비활성 거부·기존 리소스와 UI 동작을 검사했습니다. 프리팹 생성·구조 검증 메뉴는 사용자 로그로 성공을 확인했습니다. 실제 DDOL 씬 수명과 Play Mode 재진입 검증은 별도로 확인해야 합니다. 이름만 변경한 이번 수정에서는 테스트를 재실행하지 않았습니다.
