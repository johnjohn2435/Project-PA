Block Gravity 화면 배치와 게임 규칙

후속 플레이 화면 연결 완료 · 아래는 2·3단계 당시의 설계와 규칙 기록이다. 현재 표시·입력·HUD 구현 및 복사본 Play Mode 검증 결과, 원본 적용 절차는 최신 플레이 화면 안내를 따른다.

8×8 보드와 하단 조각 트레이의 배치 기준, Unity와 분리된 게임 규칙을 구현했다. UIManager와 연결할 수 있도록 턴 결과를 단계별로 전달한다.

배치 계산 구현규칙 구현Unity Edit Mode 53 / 53 통과

1080×1920, Safe Area가 전체 화면인 경우. 배치 설계도이며 실제 플레이 화면은 다음 구현 단계다.

화면 기준

  • 보드 중심은 월드 (0,0), 한 칸은 1유닛. 보드 전체는 8×8유닛이다.
  • Safe Area 안에 HUD → 보드 → 트레이 순서로 배치한다. 화면 비율이 달라도 보드는 정사각형을 유지한다.
  • 직교 카메라 위치·크기와 각 영역의 픽셀 사각형은 PlayfieldLayout.Calculate가 계산한다.
  • 기준 화면: OrthographicSize 8, 카메라 위치 (0, -0.416667, -10).
  • 블록은 기본 128×128 이미지, PPU 128, 중앙 피벗. 캐릭터의 기존 원화 규격은 별도로 유지한다.
  • 트레이 3슬롯, 조각 미리보기 한 칸 0.6유닛, 드래그 시 1유닛. 손가락 오프셋은 기준 120픽셀부터 조정한다.

레이어 표시 순서

Default 레이어에서 배경 0 → 보드 10 → 블록 20 → 프리뷰 30 → 트레이 40 → 드래그 100. 메뉴와 HUD, 팝업은 uGUI로 구성한다.

비율 대응 검증

16:9 · 19.5:9 · 20:9, 720×1280, 좌우·상하 Safe Area가 있는 화면에서 영역 겹침과 카메라 투영을 수치로 검증했다.

한 턴의 처리

배치 → 중력 정렬 → 완성 줄 동시 제거 → 재정렬 → 5회마다 중력 변경 → 트레이 소진 시 리필 → 게임 오버 검사

블록은 배치 후 각 칸이 독립적으로 움직인다. 중력은 아래 → 왼쪽 → 위 → 오른쪽 순서다. 가로·세로가 교차한 칸은 한 번만 제거한다.

연쇄 규칙의 제약

현재의 “전체 셀 중력 압축 후 완성 줄 전부 동시 제거” 방식은 일반적인 빈 직사각형 보드에서 다단 연쇄가 자연스럽게 발생하지 않는다. 반복 처리와 연쇄 배수는 준비했지만, 실제 연쇄를 핵심 재미로 만들려면 삭제 시점이나 고정 블록 같은 규칙 조정이 필요하다.

조각 구성

단일 칸, 가로·세로 2칸, 가로·세로 3칸, 정사각형 4칸, L3, L4, 코너3, T4의 10종이다. 기존의 “3칸 T”를 4칸으로 보정했고 L3과 코너3은 서로 다른 방향으로 정의했다. 모든 조각은 고정 방향이며 기본 추첨 가중치는 동일하다.

점수와 결과
  • 배치 셀당 10점. 줄 1/2/3/4개 동시 제거는 100/300/600/1000점, 이후 한 줄당 400점 추가.
  • 삭제 점수에 연쇄 단계 배수를 적용한다. 중력 변경 후에도 같은 턴의 배수를 이어 사용한다.
  • 코인은 점수 ÷ 250의 정수 부분, 최대 100개. 게임 오버 이후 보상 확정은 세션당 한 번만 허용한다.
  • 실제 저장과 보상 지급 연결은 후속 작업이다.
다른 세션의 UIManager와 연결할 방법
  1. Presenter에서 BlockGravitySession을 만든다. 기존 매니저는 게임 규칙의 의존성이 아니다.
  2. 입력과 팝업 상태를 확인한 뒤 TryPlace(slot, origin, out result)를 호출한다.
  3. result.Frames 순서대로 보드 상태·이동·삭제·점수를 표시한다. 재생 중 새 입력은 Busy로 거부된다.
  4. 재생 완료 후 CompletePresentation()을 호출한다. 이후 입력을 받거나 결과 팝업을 연다.
  5. 다음 화면 구현 단계에서 참조 어셈블리, SpriteRenderer View, 터치·마우스 입력, HUD와 팝업을 연결한다.

검증 범위와 다음 작업

Unity 6000.3.16f1의 별도 최소 프로젝트에서 새 어셈블리를 컴파일하고 Edit Mode 53개를 모두 통과했다. C# 컴파일 오류·경고는 없었다. 전체 기존 프로젝트의 통합 컴파일, Play Mode, Android 빌드와 기기 터치는 아직 확인하지 않았다.

현재 완료 범위는 화면 설계·배치 계산과 게임 규칙이다. 다음 작업은 SpriteRenderer 보드·조각 View와 입력, HUD를 연결하여 실제로 플레이할 수 있는 화면을 만드는 것이다.
