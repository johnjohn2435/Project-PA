캐릭터 테이블,
HTML과 JSON 중 무엇이 좋을까?

게임이 읽을 데이터라면 JSON이 더 적합합니다.
다만 지금 프로젝트에서는 이미 준비된 Unity 데이터 에셋을 쓰는 편이 간단합니다.

현재 추천: ScriptableObject를 기준 데이터로 유지

Unity Inspector에서 캐릭터 정보를 입력하고, 필요하면 그 데이터를 HTML 표로 보여줍니다. 캐릭터가 많아져 여러 행을 한꺼번에 수정해야 할 때 JSON이나 스프레드시트 가져오기를 추가합니다.

이 문서는 방식 선택을 돕는 추천안입니다. 게임 코드 변경, JSON 가져오기, HTML 자동 생성·편집 도구는 이번에 구현하지 않았습니다.

먼저, 세 가지 역할을 구분하면 쉽습니다

사람이 보는 화면

HTML

이미지와 표, 색상을 함께 보여주는 데 적합합니다. 저장 기능을 별도로 만들지 않은 HTML 표를 수정해도 게임 데이터는 바뀌지 않습니다.

데이터를 담는 파일

JSON

캐릭터 정보를 프로그램끼리 주고받기 좋습니다. 직접 편집할 때는 쉼표·따옴표 등 문법을 맞춰야 합니다. Unity에서 읽고 검사하는 코드가 필요합니다.

Unity 안의 데이터 카드

ScriptableObject

이름을 입력하고 이미지를 끌어 넣는 방식으로 편집합니다. 현재 프로젝트의 CharacterDefinition이 이 방식입니다.

ScriptableObject는 Unity 프로젝트에 데이터 에셋으로 저장하고 Inspector에서 연결할 수 있습니다. Unity 공식 설명

우리 프로젝트에서는 이렇게 고르면 됩니다

하고 싶은 일맞는 방법추가로 필요한 것
현재 캐릭터 3종의 이름·이미지 수정ScriptableObject — 지금 추천기존 CharacterDefinition 사용
전체 캐릭터를 그림과 함께 한눈에 보기HTML 목록기준 데이터에서 목록을 생성하는 도구
Unity 밖에서 데이터 편집·교환JSON 원본 → Unity 가져오기ID 검사, 이미지 연결, 변환 도구
캐릭터와 수치를 여러 행씩 비교·수정Excel/CSV → Unity 가져오기열 규칙과 형식 검사, 변환 도구
JSON이 더 전문적인 선택인 것은 아닙니다.
지금 손쉽게 수정하고 실수를 찾을 수 있는 방식이 좋습니다. 브라우저에서 표를 편집하는 것이 편하다면, 나중에 HTML 편집 화면 + JSON 저장을 조합할 수도 있습니다. 그 편집기는 별도 개발이 필요합니다.

지금 필요한 캐릭터 항목은 이 정도입니다

게임이 RPG 능력치를 사용하지 않으므로 공격력·방어력 같은 열부터 만들 필요는 없습니다. 현재 코드의 필드를 기준으로 시작하면 됩니다.

HTML 표가 필요해지면 같은 에셋에서 생성하도록 만들면 됩니다. HTML, JSON, 에셋을 각각 손으로 고치면 어느 값이 최신인지 헷갈리기 쉽습니다.

나중에 JSON을 원본으로 전환하면 JSON에서만 수정하고 Unity 에셋은 가져오기로 갱신하는 규칙을 적용합니다. JSON의 이미지 이름을 실제 Sprite에 연결하는 변환도 함께 필요합니다.

캐릭터 테이블과 플레이어 저장은 다른 데이터입니다

캐릭터 정의

모든 플레이어가 공유하는 이름·초상화·대표 색. 현재는 ScriptableObject에 둡니다.

플레이어 저장

내가 선택한 캐릭터, 보유 캐릭터, 코인. 기존 player-save.json에 저장합니다. 이 JSON은 캐릭터 원본 테이블이 아닙니다.

추천하는 첫 작업

  1. 현재 3종의 이름·Portrait·대표 색을 CharacterDefinition에 정리합니다.
  2. 선택 화면에서 데이터와 원화가 올바르게 반영되는지 확인합니다.
  3. 일괄 편집이 불편해지는 시점에 표 편집 또는 JSON 가져오기를 추가합니다.

즉, 지금은 Unity에서 간단히 관리하고, HTML은 사람이 보는 목록으로 쓰는 구성이 가장 부담이 적습니다.

기존 코드에 근거한 추천이며 사용자의 형식 확정은 아직 없습니다. JSON 직렬화의 Unity 지원 범위는 Unity JSON 문서에서 확인할 수 있습니다.
