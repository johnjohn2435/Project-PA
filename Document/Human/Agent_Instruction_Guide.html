다시 실행할 검증

실제 테스트 이름과 CLI 예시, 씬 진입·조작·기대 결과, 기기 검증의 한계를 안내합니다.

기존 프로젝트에 맞춘 부분

항목현재 적용 기준
리소스로컬 빌드에 포함하고 부트에서 준비합니다. 플레이 중 즉석 로딩이나 원격 패치를 추가하지 않습니다.
문자열JSON 테이블의 한국어·영어가 원본입니다. 로그·오류도 기존 사용자 규칙을 따릅니다. 부트 최초 문구는 테이블에서 프리팹에 구운 값을 유지합니다.
UI프리팹, UIManager의 FIFO 명령·프레임·수명, 현재 원형 게임 배지와 별도 친구 선택창을 유지합니다.
캐릭터·게임다람이의 기존 저장 ID, 푸들 추가, 원판 접촉 사망, 시간 분신의 길막 전용 규칙 등 최신 결정에 맞췄습니다.
문서기존 AI Markdown / 사람용 HTML 배치를 보존하고 구조 안내·기능 색인·TODO를 연결했습니다.
제외한 템플릿 예시서버 분리·ECS·Addressables·존재하지 않는 로그 래퍼/이벤트 버스는 구현 규칙으로 추가하지 않았습니다.

두 번째 묶음에서 추가한 것

반복 작업 순서

문자열, UI, 캐릭터, 미니게임 추가를 실제 코드와 도구 기준의 네 가지 절차로 정리했습니다.

동시 수정 체크리스트

저장 해금·게임 라우팅·UI 수명·문자열·부트·렌더러의 여섯 항목에서 검사로 잡히는 부분과 남는 빈틈을 구분했습니다.

구조 결정 기록

선택한 이유와 기각한 대안을 남기는 ADR 틀과 색인을 마련했습니다. 기존 결정을 새 승인으로 만들지 않습니다.

기능 문서는 실행 흐름 중심으로 작성하고 실제 수정하는 문서만 점진적으로 바꿉니다. 빠른 규칙 검사와 엔진 통합 검사를 구분하며, 도구 변경은 작은 실제 입력으로도 확인합니다.

충돌 규칙은 이렇게 조정했습니다

항목적용한 기준
커밋·푸시사용자 변경 자동 포함 금지. 현재 브랜치와 원격 대상을 확인하고 필요한 통합·검증 후 전송 결과를 확인합니다. 기본 브랜치 갱신은 강제하지 않습니다.
문서 원본별도 작성 HTML은 계속 원본으로 편집합니다. 실제 변환기와 명령이 있는 출력만 생성물로 취급합니다. 문서를 일괄 이동하지 않습니다.
검증정적·수동·자동 확인을 구분해 보고합니다. 변경 영향에 맞춰 검사하고 넓은 공용 변경에서 전체 테스트로 확대합니다.
하위 에이전트명시적 요청·지정이 있을 때 범위를 나눠 사용합니다. 큰 작업이라는 이유만으로 자동 실행하지 않습니다.

검증과 남은 범위

이번 적용의 확인 대상은 문서의 로컬 링크·경로, 템플릿 빈칸, 자동 진입 파일, 기존 코드·설정과의 일치입니다. Unity 게임 테스트, 화면 조작, Android 빌드·실기기 확인은 이번 문서 변경에 포함하지 않습니다.

과거 문서의 테스트 통과 수는 당시 결과입니다. 기존 로그 문구와 생성 도구의 오래된 백업 경로는 후속 검토 항목으로 구분했습니다.

원본 보존과 운영 방식

기존 명세·결정·상태 기록과 사람용 문서는 옮기지 않습니다. 새 현재 계약에서 근거 문서로 연결합니다. 공통 규칙을 기능별 문서에 반복하지 않고 바뀐 계약만 해당 위치에서 갱신합니다.

CLAUDE.md는 AGENTS.md 한 줄 참조를 사용합니다. Client 폴더에서 시작할 때도 상위 지침으로 연결됩니다. 새 기능 문서 틀은 필요할 때만 복사합니다.
