POCKET ARCADE / STRING TABLE

표시 문구는 테이블에서,
코드는 문자열 키로.

196개 문구를 한국어·영어로 관리합니다. 기본 언어는 한국어이며 게임 중에는 부트에서 준비한 테이블만 조회합니다.

문자열 테이블·부트 연결·UI 코드 구현 완료. Android Edit Mode 117/117 통과. 키 누락, 중복, 번역 컬럼 누락, 형식 인자, 언어 변경, 기존 UI·리소스 기능을 검사했습니다.
기존 프리팹에 번역 키와 한글 폰트를 연결하는 메뉴는 사용자 실행이 필요합니다. 실제 화면·줄바꿈·모바일 표시와 프리팹 적용 메뉴는 이번 자동 테스트에서 실행하지 않았습니다.

Unity에서 한 번 적용

  1. Play Mode를 종료하고 컴파일 완료를 기다립니다.
  2. Pocket Arcade → Localization → 1. Apply String Table And Korean Font를 실행합니다.
  3. Pocket Arcade → Localization → 2. Validate String Table로 확인합니다.
  4. BootScene에서 Play 후 허브·캐릭터·설정·메시지박스·게임 진입 문구를 확인합니다.
  5. Localization → Preview English (Play Mode) / Preview Korean (Play Mode)로 언어를 비교합니다.

메뉴는 UI 프리팹과 씬을 Client/Logs/StringTableBackup/에 백업합니다. 중첩 프리팹과 동적 라벨을 구분하여 연결합니다. 원본 통합 매니저의 Legacy 프리팹은 적용 대상이 아닙니다.

어디를 수정하나요?

Client/Assets/_Project/Resources/Data/StringTable.json

{
  "key": "hub.choose_game",
  "ko": "게임 선택",
  "en": "Choose a game"
}

key는 중복되지 않는 문자열 ID, ko는 한국어, en은 영어입니다. 문구 변경은 이 JSON을 편집하면 됩니다. 키를 바꾸면 참조 코드·프리팹 키도 함께 바꿔야 합니다. 컬럼 누락이나 중복 키가 있으면 부트 로딩이 실패합니다.

새 캐릭터 이름: character.{캐릭터ID}.name
새 게임 이름: game.{게임ID}.name
기존 캐릭터 ID와 원화는 그대로 유지합니다. ScriptableObject의 옛 displayName 대신 ID에서 구한 문자열 키로 이름을 조회합니다.

로딩과 코드 구조

① BootScene

StringTable.json을 먼저 비동기 로드합니다. 로딩 안내부터 번역을 사용하고, 같은 TextAsset을 ResourceManager의 세션 캐시에 등록합니다.

② DataManager

Strings로 테이블을 제공하고 SetLanguage로 언어를 변경합니다. 별도 통합 매니저나 즉석 리소스 로딩을 추가하지 않습니다.

③ View

정적 TMP 라벨은 LocalizedText의 key를 사용합니다. 코인·캐릭터 카드·게임 안내는 View/Controller가 형식 인자를 전달합니다.

L10n.Text("common.ok");
L10n.Format("hub.coins", coins);
DataManager.Instance.SetLanguage(GameLanguage.English);

문장 전체를 하나의 행으로 저장합니다. {0}, {1}은 두 언어에서 같은 번호를 사용하되 위치를 바꿀 수 있습니다. 키가 없으면 [키]가 표시되어 누락을 확인할 수 있습니다.

언어 선택은 현재 세션에 적용됩니다. 설정 화면 언어 선택 UI와 선택 언어 저장은 이번 범위에 포함하지 않았습니다. 이미 표시 중인 메시지박스·토스트의 본문은 생성 시 문구를 유지하며 새 요청부터 바뀐 언어가 적용됩니다.

한글 폰트와 관리 범위

기존 Liberation Sans는 한글 글리프가 없어, Google Fonts의 나눔고딕 원본과 OFL 라이선스를 Client/Assets/_Project/Fonts/에 추가했습니다. 적용 메뉴에서 TMP 폰트를 만들고 테이블 글자를 미리 채워 UI에 연결합니다. 게임 실행 중 폰트를 다운로드하지 않습니다.

테이블 문구 변경 후 적용 메뉴를 다시 실행하면 프리팹 미리보기와 글리프가 갱신됩니다. 실제 Android 화면에서 글자 잘림·자동 크기·줄바꿈은 별도로 확인하세요.

앞으로 코드에 추가하는 모든 사람이 읽는 문구는 테이블에 저장합니다. 신규 로그·오류 메시지도 포함하며, 경로·리소스 ID·직렬화 필드명 등 기술 식별자는 코드에 둘 수 있습니다. 현재 전환 완료 범위는 게임 표시 문구이며, 기존 개발 로그·예외는 아직 코드에 남아 있습니다. 최신 규칙은 AGENTS.md에 기록되어 있습니다.
