이 문서는 "어떤 클래스가 있는가"가 아니라 **"무슨 일이 어떤 순서로 일어나는가"**를 축으로 쓴다.
코드만 읽어서는 알기 어려운 계약을 적는다: 누가 소유하는가, 어떤 순서를 지켜야 하는가,
무엇을 하면 안 되는가, 왜 그렇게 했는가. 코드를 그대로 옮긴 설명과 작업 일지는 쓰지 않는다.

## 1. 이 문서가 답하는 질문

<한 문단. 이 기능의 책임을 질문형으로. 예: "우편을 열고, 읽고, 첨부를 받을 때 누가 요청을 보내고 누가 상태를 갖는가?">

## 2. 전체 지도

대표 시나리오의 시간 순서나 호출 트리를 그린다. 시나리오가 여럿이면 "시나리오 → 절" 안내표를 붙인다.

```
<버튼 클릭> → <창 열기> → <요청> → <응답 적용> → <화면 갱신>
```

## 3. 계약과 불변식

이 기능 전체가 지키는 규칙 5~8개. 각 항목은 한두 줄, 상세는 아래 절로 링크한다.

- 상태를 소유하는 객체와 수명: 언제 만들어지고 언제 초기화·파괴되는가.
- 화면이 닫혀 있어도 유지되는 것과 화면과 함께 사라지는 것.
- 상태를 확정하는 주체와 실패 시 보존할 것. 현재 로컬 게임에 없는 서버 계약은 추가하지 않는다.
- 코드에 두면 안 되고 테이블·설정이 소유해야 하는 규칙.

> **주의**: 함정이나 직관과 다른 결정은 이렇게 따로 표시한다. 이 문서에서 가장 값진 내용이므로
> 문서를 개편해도 그대로 보존한다.

## 4. 흐름 (시나리오 순서)

절의 순서는 클래스 목록이 아니라 흐름 순서다. 각 단계에서 해당 코드를 설명하고 파일 경로를 단다.

### 4.1 <진입>

- 사용자가 들어오는 경로(버튼·메뉴·이벤트)와 진입 코드.

### 4.2 <처리와 결과 적용>

- 요청 종류, 보내는 조건, 중복 요청 방지.
- 성공·실패 응답이 상태를 어떻게 바꾸는가. 실패 시 무엇을 보존하는가.

### 4.3 <비동기 완료·취소·씬 전환>

- 적용되는 경우 시간 초과, 늦은 완료, 재진입, 씬 전환 중의 처리. 서버 연동 절은 실제로 도입한 경우에만 작성한다.

### 4.4 외부 결합 지점

다른 시스템이 이 기능을 끊거나 막는 지점. 검색하지 않으면 보이지 않는 결합을 표로 둔다.

## 8. 검증

- 테스트 명령과 실제 게임에서 확인할 조작·기대 결과. 상세는 [검증 안내](Verification.md)에 둔다.

## 부록

본문 흐름을 끊는 참조 표(패킷 값, 상수, "클래스 → 담당 절" 색인)는 여기에 둔다.

---

### 작성 기준

- **표는 "코드에 없는 결정이나 함정을 담는가"로 판단한다.**
  실행 순서, 책임 분담, 정책 분기, 순서를 바꾸면 안 되는 값은 남긴다.
  enum·필드·메서드 목록을 그대로 비추는 표는 만들지 않는다. 코드의 사본은 조용히 낡는다.
  본문 한 문장과 파일 경로로 대신한다.
- **기존 문서는 손댈 때만 이 골격으로 바꾼다.** 내용 변경 없이 여러 문서를 한꺼번에 개편하지 않는다.
  검증할 수 없는 큰 변경이 되기 때문이다.
- 개편 전에 핵심 수치(상수·우선순위·대응 관계)를 코드와 대조하고,
  개편 후에는 이전 판의 핵심 식별자가 빠지지 않았는지 검색으로 확인한다.
- 다른 문서가 이 문서의 절을 번호로 가리키고 있으면 함께 고친다.
